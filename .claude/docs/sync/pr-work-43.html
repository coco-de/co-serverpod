동기화 엔진이 serverpod_offline_sync 포크로 넘어가면서 앞으로 쓰지 않을 순수 Dart 코어 co_offline_sync와 Flutter + Drift 클라이언트 co_sync를 지웠다. 저장소 안에서 두 패키지를 가리키던 빌드 스크립트·CI job·릴리스 설정·README 안내도 함께 걷어냈다. 남은 패키지의 코드는 한 줄도 바뀌지 않았다.

리뷰 가이드 — 여기부터 보세요

  1. .github/workflows/offline-sync.yml — 두 job과 두 경로만 빠졌는지, 남은 serverpod-offline-sync job과 나머지 트리거 경로가 그대로인지.
  2. release-please-config.json + .release-please-manifest.json — 두 파일의 패키지 키 집합이 서로 같은지(인증 8개). 남은 키는 모두 실제 디렉터리를 가리킨다.
  3. pubspec.yaml — 지운 스크립트는 삭제된 디렉터리로 cd 하던 두 개뿐이다. 이름이 비슷한 serverpod-offline-sync:* 스크립트는 남아 있다.
  4. README.md — 개발 절차의 두 단락을 하나로 합쳤다. 포크를 루트 workspace에 넣지 않는 이유 중 co_sync의 drift_dev 충돌 항목은 더 이상 해당하지 않아 뺐다 (남은 패키지에는 drift·drift_dev 의존이 없다).
  5. 삭제된 70개 파일 — 두 패키지 디렉터리 밖의 파일은 없다. 훑어보기만 하면 된다.

왜 이렇게 했나

  • 폐기 표시 대신 삭제. 남은 소비자는 모두 co-serverpod를 커밋 SHA로 고정하고 있고, 그 SHA는 main의 조상이라 삭제 뒤에도 그대로 해석된다. 남겨 두면 CI 두 job과 릴리스 추적, README 안내가 계속 비용과 혼선을 만든다.
  • 릴리스 설정에서도 뺐다. 남겨 두면 release-please가 존재하지 않는 경로를 계속 추적한다. 이 커밋은 남은 패키지 경로를 건드리지 않으므로 어느 패키지의 버전도 올리지 않는다.
  • 태그 co_offline_sync-v0.2.0은 남겼다. 과거 릴리스를 가리키는 참조라 지울 이유가 없다.
  • 포크의 co_sync 대응 서술은 남겼다. OfflineSyncFailureReason의 clock_drift 대응 주석, README의 CoSyncStatus → OfflineSyncStatus 표 등 11줄이다. 아직 co_sync를 쓰는 앱이 포크로 옮길 때 읽는 매핑이고, 링크가 아니라 깨지지도 않는다.
